# 题库编审与发布

| 文件 | 维护内容 |
| --- | --- |
| `content/topics.json` | 14 个已批准专题，数组顺序对应菜单顺序 |
| `content/sources.json` | 来源、出版机构、文书与网页日期、施行日期、可获取状态 |
| `content/knowledge-points.json` | 原子事实、判断范围、主专题、依据条页段 |
| `content/questions.json` | 题干、稳定选项 UUID、答案集合、解析、证据和两轮审查 |
| `content/duplicate-reviews.json` | 新库重复候选对的处置 |
| `research/review/legacy-candidates.csv` | 旧候选的审查记录 |

创建题目和选项时生成 UUID。修订、移动专题和调整位置沿用原题 ID。如内容改成另一个考点，新增题目并保留旧条目为 `withdrawn`。判分使用选项 UUID。

## 每题发布步骤

1. 从来源台账取原文，定位适用时间和条段，先记录知识点再出题。第三方题集用于了解考法、发现漏点。
2. 作者检查题干、全部选项、正确集合、总解析及逐项理由。第二轮先独立据原文解题，再对照初审结果和解析。审题依据和结果写进 JSON。
3. 校验审核卡的内容摘要。修改题干、选项、排序、解析或证据时，新的摘要要求新的复审。编审可以用 `questionRevision` 得到所审内容的摘要。
4. 对规范化重复、字符三元组召回和同知识点相似题进行核定。将丢弃项标记为 `withdrawn` 或留在候选台账，将可独立考查的题对写入重复核查记录。
5. 达标题标为 `ready`。构建产出按专题和顺序分片的 CDN JSON。线上发布设置 `REQUIRE_COMPLETE_BANK=1`，并在数据库同步时使用 `--release`。缺覆盖、重复未处置或分布不合格时退出。

情绪线索题和全选多选题的上限均为 10%，对全库和各专题分别计算。四选单选检查各位置计数，四选多选分别统计正确项数量与正确位置。其他选项数量独立报告。程序验证记录完整性及指标，事实复核证据保存于每题。
