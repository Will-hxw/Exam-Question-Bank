# 性能与运行验证

## 复跑端到端测试

准备独立、允许 `CREATEDB` 的环回 PostgreSQL，设置 `TEST_DATABASE_URL` 后运行 `npm run test:e2e`。测试会创建随机临时库和临时生产构建，结束时清理。

如需验证浏览器登录和学习流程，安装 Python Playwright 与 Chromium，并设置 `EQB_TEST_BROWSER=1`。可用 `EQB_TEST_PYTHON` 指定 Python 可执行文件。测试在隔离环境通过登录界面使用测试账号，并覆盖刷题、收藏、错题、模考和草稿恢复。

## 历史本地测试环境

2026-11-23。Windows 上运行 Next.js 16.4.6 生产构建和 Node.js 24.5.0，数据库为 WSL 的 PostgreSQL 16.15。Next、PostgreSQL 和 Auth 测试上游均走回环网络。每次建立独立数据库，运行实际迁移并放入 52 道合成测试题。构建不复制静态题库分片，以便实测 PostgreSQL 回源。Auth 上游只提供本地合成身份，应用的会话校验、邮件验证门槛、同源和所有者检查、PostgreSQL 限速及学习写入均使用真实代码路径。

HTTP 时间从请求发起计到完整响应体读完，响应体尺寸为 JSON 解码后 UTF-8 字节。冷读指新 Next Data Cache 的首条请求，PostgreSQL 进程已启动且健康检查已经取得连接。热读采用 30 条串行请求，p95 使用最近秩。浏览器使用新建的 390 × 844 CSS px Chromium 上下文和本地服务器，首题指标从导航开始计到选项可点。切题指标含 Playwright 点击与 DOM 可见断言的耗时。

## 本地通过项

- 读取 PostgreSQL 的 14 个专题、15 题练习批次、中文关键词及第二页游标，返回正确的答案和逐项理由。普通列表不附标准答案，交卷前的试卷也不含答案或解析。
- 匿名跳登录，未验证邮箱不能读取个人记录。两个测试账号的收藏、作答及考试处于独立分区。个人数据、Auth 和错误响应应用 `private, no-store`。
- 四次并行发送同一个作答事件只记一次。旧内容摘要作答被拒绝。50 题考试保存草稿、拒绝旧草稿修订、按标准答案判分。重复交卷仍只生成 50 条该卷作答记录。
- 数据库直接改名并下架一题后，固定解析立即返回 404，目录和首批已缓存的旧结果仍可看到。无效令牌请求失效接口返回 404，旧缓存持续。授权失效后，首次正常目录和练习请求同时读到新专题名与新题量，下架题从首批消失。发送失效请求到两个更新响应完整可读用时 14.63 ms（1 次）。
- Chromium 经实际 API 使用断网队列，仅在重新联网后取得写入成功，统计更新为已练习 1 题。浏览器完成 50 题组卷、草稿刷新续答和交卷。随后直接查 PostgreSQL，确认该测试账号有 1 条练习作答和 50 条考试作答。

## 2026-11-26 作者对话本地对比

对比改动前后的 Next.js 生产构建。两版使用同一题库、回环 PostgreSQL 和带 95 ms 延迟的合成 Auth。桌面 Chromium 模拟 390 × 844 手机，每版使用 6 个全新浏览器上下文。浏览器设置 100 ms 延迟、约 550 KB/s 下载限速。登录耗时包含 Playwright 的输入框和首题断言。聊天耗时从按下入口算到浏览器检测到消息节点出现或头像解码完成。

| 操作 | 改动前 p50 | 改动后 p50 |
| --- | ---: | ---: |
| 登录页邮箱输入框可用 | 148 ms | 150 ms |
| 提交登录到首题可答 | 1,953 ms | 1,946 ms |
| 首次打开群聊到首条消息出现 | 266 ms | 164 ms |
| 打开群聊到作者头像解码完成 | 395 ms | 164 ms |
| 返回后再次打开群聊到消息出现 | 144 ms | 18 ms |

成功登录后的额外浏览器会话查询由每次 1 次减为 0 次。以上为小样本本地对比，正式站网络结果仍需上线后在真实设备采集。

## 2026-11-26 首页、模考与聊天复测

对比主线 `1f8dec9` 与本次改动，使用同一份 750 题题库、隔离 PostgreSQL 和增加 130 ms 延迟的合成认证服务。390 × 844 的 Chromium 模拟 110 ms 网络延迟与 550 KiB/s 下行带宽。两版交替各运行 5 个新的浏览器上下文。

| 操作 | 改动前 p50 | 改动后 p50 |
| --- | ---: | ---: |
| 首页刷新到首题可答 | 1,300 ms | 789 ms |
| 首页刷新到显示练习统计 | 1,303 ms | 793 ms |
| 模考刷新到可继续草稿 | 1,301 ms | 794 ms |

首页统计和模考历史由服务端随页面启动读取，浏览器各减少一次独立请求。普通刷题将校验过的首批题随页面传给浏览器。聊天端到端测试暂停首条发送请求时，仍在约 48 ms 显示发送中气泡，失败后复用同一消息编号重发。

## 上线后的大陆实测

在移动、联通、电信的真实网络分别执行。至少在两个时段采样，注明设备、浏览器、城市、网络类型、样本量、成功数和失败类型。同一网络分别记录新浏览器和热缓存请求，另记录 Neon 已休眠后的首次请求。跨网或企业代理环境单列。

1. 使用浏览器性能面板采集 LCP、CLS 和交互延迟。登录后记录首次打开到第一题可作答、连续切换已预取题、中文搜索翻页以及开始与交卷 50 题考试的时间。首题按不超过 3 s、LCP 按不超过 2.5 s、CLS 按不超过 0.1 查验，明确实验室响应延迟与真实用户 INP 的区别。
2. 对清单及同一分片分别记录冷、热请求的 HTTP 时间、状态码、响应体大小及实际 EdgeOne 命中标识。验证分片长缓存、清单可重验、个人读写禁止共享缓存，发布改题后重验清单并确认新旧资产切换。
3. 使用本人或已授权的邮箱登记登录、验证邮件、找回密码、答题保存和第二台设备恢复。记录登录接口、邮件投递和同步的 p50、p95，覆盖短时断网后恢复与失败重试。3000 ms 的首批目标与 1500 ms 的正常后台同步目标均按大陆样本判定。

待补的是 EdgeOne 公共缓存命中、Neon 跨境延迟和休眠，以及大陆三网的性能分布。正式邮件已确认有实际收件，投递延迟仍缺多线路采样。 [验收证据](ACCEPTANCE.md)
